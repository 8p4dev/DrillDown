# R4 — 내용 입력·재구성 (2026-11-08)

조사 범위: 222노드 트리를 **만들고 고치고 옮기고 백업하는** 과정. 코드 수정 없음.
방법: 포트 4304 서버(`DATA_DIR=.research-data/R4`, 가짜 로그인 `R4`) + Playwright(msedge) 스크립트로 실제 조작. 표기 — **[실사용]** 브라우저에서 직접 재현, **[코드]** 코드에서 확인, **추정** 은 근거 없는 추론.
스크린샷: `img/R4_after_paste.png`(222노드 붙여넣기 직후), `img/R4_delete_toast.png`(서브트리 삭제 토스트), `img/R4_mobile.png`(390px 편집 화면).

## 요약
1. **처음 한 번 붙여넣기는 아주 잘 된다**(222줄 → 222노드 0.7초, 내보내기 왕복 일치). 문제는 그 **다음**이다: 다시 붙이면 조용히 중복되고, 메모·별칭은 붙여넣기로 들어갈 길이 없고, 서브트리는 같은 트리 안에서 잘라내기로만 옮길 수 있다.
2. **백업이 사실상 없다.** "데이터 내보내기" JSON에 트리·노드가 하나도 없고(학습 이벤트+계정 정보만), 가져오기 기능도 없다. 삭제된 노드는 새로고침하면 되돌릴 수 없다.
3. **모바일에서는 재구성이 불가능하다.** 자식 추가(Tab)·이동(Ctrl+X/V)·삭제(Delete)·실행 취소(Ctrl+Z)가 모두 키보드 전용이고 화면 버튼이 없다. 별칭(`aliases`)은 PC에서도 입력 UI가 없다.
