# R3 — 큰 트리·많은 트리 학습 (플래시·빈칸·백지·복습)

작성 2026-11-08, 워커 R3. 앱 실행: 포트 4303, DATA_DIR `.research-data/R3`, Edge(Playwright) 1366×900 + 390×844. 예시 트리(222노드)를 "개요 붙여넣기"로 만들고 플래시 81장 전부 평가(자식 221개, 70% 알음), 빈칸·백지 전체 범위 열기, 복기용 트리 4개 추가(백지 빈 채점), `Date` 이동(+1·3·7·14·30일)으로 복습 큐를 측정했다. 서버는 끝나고 종료함.
표시: **[실사용]** 브라우저에서 직접 겪음·측정 / **[코드]** 코드에서 추론 / **[추정]** 근거 약함.

## 요약
1. 학습 단위가 "트리 전체"가 기본이라 예시 트리 하나로 플래시 81장·평가 221회, 빈칸 카드 141장(캔버스 높이 9,590px), 백지 카드 221장이 한 세션에 나온다. 범위 선택은 빈칸·백지에만 있고(81개 평면 드롭다운, `방법`·`대책` 중복), 플래시엔 없다.
2. 복습은 상한·분산이 없다. 같은 날 평가한 221개가 **+7일에 한꺼번에** 기한이 되고(FSRS fuzz 꺼짐), 트리 5개에서 배지가 962 → 1,105까지 올라갔다. 목록은 긴급도가 아니라 최근 수정순이고, "전체 복습"이 없어 트리마다 따로 시작해야 한다.
3. 복습 화면에는 경로(빵부스러기)가 없어 `방법`·`대책` 같은 카드가 무슨 공격의 방법인지 모른 채 나온다. 백지 채점은 부모를 **제목**으로 비교해서, 다른 공격의 `방법` 아래에 붙여도 정답이 된다.

## 학습 과학 근거 (간단)
- **간격 반복**: 이득은 "적당한 양을 매일" 할 때 나온다. 대표 SRS(Anki)는 하루 신규·리뷰 상한과 간격 fuzz로 몰림을 막는다 — 현재 둘 다 없음(P6·P7).
- **인출 단서/부호화 특수성(Tulving)**: 학습 때 본 맥락(경로)이 시험 때 없으면 인출률이 떨어진다 → P5는 단순 UI 누락이 아니라 학습 효과 문제.
- **교차(interleaving)**: 비슷한 개념(공격 유형들)을 섞어 풀면 변별 학습이 좋아진다(Rohrer & Taylor 2007, Kornell & Bjork 2008). 다만 맥락이 붙어 있어야 의미가 있어 P5 해결이 전제(P16).
- **청크·세션 길이**: 한 세션은 10~20분(카드 수십 장)이 일반적 권고 [추정] → 깊이1 서브트리(노드 6~41)가 자연스러운 단위.
