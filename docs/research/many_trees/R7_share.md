# R7 — 공유·갤러리·복제: 트리가 많고 클 때 (2026-11-08)

조사 방법: 포트 4307, `DATA_DIR=.research-data/R7`, 가짜 로그인 `R7`·`R7b`·`R7s1`·`R7s2`, Edge + 임시 Playwright 스크립트.
예시 트리(222노드)를 개요 붙여넣기로 만들어 공개 → 비로그인·다른 사용자로 공유 보기·학습·복제 → 원본 수정 → 갤러리에 공개 트리 52개(시드 50 + 원본 + 복제본 재공개)를 놓고 둘러봄.
표시: **[실사용]** 브라우저로 직접 겪음 · **[코드]** 코드에서 확인 · **[추정]** 확인 안 됨.

## 요약
1. 큰 트리의 공유 보기는 222노드를 접기·검색 없이 한 줄로 전부 펼쳐 보인다(데스크톱 8,844px, 폰 11,003px ≈ 13화면). 학습 범위를 고르는 UI도 없어서 빈칸 탭은 카드 141~143장을 한 번에 깐다.
2. 복제 쪽 문제: 복제한 뒤 원본이 바뀌어도 알 방법이 없다(복제본 222 vs 원본 224, 어디에도 표시 없음). 같은 트리를 다시 복제해도 경고가 없어 목록에 똑같은 카드가 쌓이고, 복제 수도 부풀려진다.
3. 갤러리는 메뉴에 들어가는 링크가 없고, 검색·분류도 없다. 카드 정보가 적어 같은 제목(첫 페이지에서만 5쌍)이나 원본/복제본(나란히 노출)을 구분할 수 없다. 공개 트리 수가 50개를 넘으면 원하는 트리를 찾기 어렵다.

### 우선순위 제안 (내 평가)
1. **S1+S2**(공유 보기 접기 + "여기부터 학습", S): 공유받은 사람이 큰 트리를 실제로 쓸 수 있게 하는 데 가장 효과가 크다.
2. **S6+S7+S8 갱신일**(갤러리 링크·제목 검색, XS~S): 갤러리를 켜기로 한다면 필수다. 안 켜면 전부 불필요하다.
3. **S4**(중복 복제 확인, S): 목록 중복을 근본적으로 막고 S5도 해결한다.
4. **S3 1단계**(원본 갱신 표시, S~M): 사용자 결정이 필요하다(04가 범위 밖으로 둔 기능).
