## 1. 결론 3줄
1. **서버까지 영구화되는 데이터 손상 2건이 재현됐다**: 새 기기 첫 로그인 시 트리 구조가 망가짐(D1), 201번째 트리가 동기화를 통째로 멈춤(D2). 둘 다 `src/core/sync/engine.ts` 약 20줄.
2. 사용 불편의 대부분은 **"큰 트리에서 지금 어디·무엇을 보고 있는지"** 문제다 — 공통 기반 3개(서브트리 범위 `?root=`, 경로 표시, 보기 깊이)로 편집·학습·공유 문제 약 15개가 함께 풀린다.
3. 편집 가능한 개요 모드·폴더/태그·다중 선택·드래그 재부모 같은 큰 기능은 **기각/보류** — 더 작은 안으로 같은 효과를 낸다.

## 5. 해결안 자체 평가 — 오케스트레이터 의견
- **신뢰도 높음**: P0 8개. 모두 코드 위치 확정 + 4건은 E2가 직접 재현. 수정이 작아 위험도 낮다. 단 D2는 "격리"로 고치면 노드 유실이 생긴다는 E2 지적이 핵심 — 구현 시 반드시 '보류'.
- **효과 대비 공수 최고**: T2 경로(복습 맥락 문제가 사용자 예시 트리의 '방법'·'대책' 30여 개에 직접 해당). T3는 E1의 가장 좋은 판단 — 워커 3명의 안이 서로 막던 충돌을 변수 하나로 해소.
- **불확실**: P1 공수 2~3주는 추정. 저장소 퇴출(U05)·스크린리더 항목은 실기기 미검증. 1,000노드 이상 성능(U21)은 사용자 트리(222)에선 문제없어 P2로 미룬 판단이 맞는지는 사용 패턴에 달림.
- **E1과 E2가 갈린 곳**: fuzz(E1 P1 채택 / E2 효과 작음) → 1줄이라 넣되 하루 상한(Q8) 판단을 앞당길 것. 휴지통(E1 로컬 7일 / E2 서버 목록) → 로그인은 서버 목록, 비로그인은 로컬 7일로 둘 다.
