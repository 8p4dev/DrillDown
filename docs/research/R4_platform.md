## 항목별 설명

1. **전체 백업·복원** — Dexie 5개 테이블(trees·nodes·srs·events·attempts)을 버전 필드가 있는 JSON 하나로 내보내고, 가져올 때는 "덮어쓰기 / 새 트리로 추가"를 고르게 한다. 현재의 ⤓(학습 기록 내보내기)는 이벤트만 담아 복원할 수 없다. 서버가 없는 지금 단계에서 데이터 유실을 막는 유일한 수단이다.
   UX: 트리 목록 ⋯ 메뉴의 "백업 파일 저장"을 누르면 `drilldown-backup-2026-11-02.json`이 내려받아진다. "백업에서 복원"으로 파일을 고르면 미리 보기(트리 7개·카드 412장)를 보여 준 뒤 확인을 받는다.
2. **저장소 영구화 + 백업 경과 알림** — 첫 트리를 만들 때 `navigator.storage.persist()`를 한 번 호출한다. 마지막 백업 날짜를 저장해 두고, 14일이 지나면 배너로 알린다. iOS에서는 persist가 거부될 수 있으니 이 알림이 실질적인 안전장치다.
   UX: 트리 목록 상단에 "마지막 백업 16일 전 · 지금 백업" 띠가 뜨고, 한 번 누르면 #1이 실행된다.
3. **개선: 설치형 PWA 완성** — manifest에 192·512 아이콘(maskable 포함)을 넣고, `beforeinstallprompt`를 받아 직접 설치 버튼을 띄운다. iOS는 이 이벤트가 없으므로 "공유 → 홈 화면에 추가" 안내를 1회 보여 준다. 이 작업만으로 #11 웹 푸시와 #9 share_target이 가능해진다.
   UX: 세 번째 학습 세션을 마친 뒤 토스트로 "홈 화면에 추가하면 바로 열려요 [설치]"를 1회 보여 준다.
4. **숙련도 대시보드** — 트리별로 노드 상태 분포(초록·연두·노랑·빨강), 회독(백지 시도)별 재현율 추이, "3회 이상 틀린 가지 Top 10"을 보여 준다. 11 §5의 성공 기준인 "회독별 자동 인정 재현율 향상"을 사용자에게도 그대로 보여 주는 화면이다. 가지를 누르면 그 가지만 드릴다운이나 백지 퀴즈로 바로 들어간다.
   UX: 트리 헤더의 "통계" 탭에서 "1회차 54% → 3회차 78%" 선 그래프 아래 빨간 가지 목록을 누르면 해당 서브트리 퀴즈가 시작된다.
5. **스트릭 + 프리즈** — 하루에 인출 행동(플래시카드 1장 이상 또는 퀴즈 1회)을 하면 스트릭으로 센다. 단순 열람은 세지 않는다. 시험 수험생은 아프거나 모의고사 날 빠지기 쉬우므로, 주 1회 자동 프리즈를 기본으로 준다. 날짜는 로컬 자정 기준으로 자른다(#7 DST 사례).
   UX: 오늘의 복습을 끝내면 불꽃 아이콘 숫자가 12 → 13으로 올라가는 마이크로 인터랙션이 나온다.
6. **일일 인출 목표** — 목표 단위는 "복습 카드 N장"과 "백지 퀴즈 1회" 두 가지다. 기본값은 FSRS 당일 due 수에서 자동으로 잡는다. 목표에 가까워질 때 진행 바를 강조해 마지막 몇 장을 끝내게 한다.
   UX: 오늘의 복습 화면 상단에 "18/20 · 2장 남음" 진행 바가 있고, 다 채우면 초록으로 바뀐다.
7. **학습 히트맵** — `events`에서 날짜별 인출 수를 세어 1년치 잔디를 그린다. 미래 칸에는 FSRS due 예측량을 옅게 표시한다. 05는 히트맵을 유료(전체 기간)와 무료(14일)로 나눴지만, 11 전제에서는 전부 무료다.
   UX: 통계 화면 맨 위에 잔디가 있고, 칸을 누르면 "10/28 · 카드 46장 · 백지 2회"가 툴팁으로 뜬다.
8. **시험일 D-day + 역산** — 시험일을 넣으면 D-day를 표시하고, 남은 기간 안에 모든 노드를 최소 N회 돌도록 하루 분량을 계산한다. 시험이 가까워지면 FSRS 목표 보유율(desired retention)을 올리는 방식도 검토한다 [미확인: FSRS 파라미터 조정 효과]. R1(시험 대비)과 겹치므로 통합 때 하나로 묶는다.
   UX: 트리 목록 상단에 "노무사 2차 D-87 · 오늘 31장"이 고정되어 있다.
9. **트리 파일 공유** — 트리 하나(노드 + 선택적으로 내 SRS 제외)를 `.drilldown.json`으로 저장하고, 모바일에서는 `navigator.share({files})`로 카카오톡 등에 바로 보낸다. 받은 쪽은 파일을 열거나 가져오기로 추가한다. 서버 없이 시드 트리 배포(06·11 GTM)를 지금 바로 할 수 있다.
   UX: 트리 ⋯ 메뉴 "공유"를 누르면 OS 공유 시트가 뜬다. 받은 사람이 파일을 열면 "근로기준법 해고 (노드 84개) 추가할까요?" 확인이 나온다.
10. **읽기 전용 공유 링크** — Pi 서버(11 §2)에 트리 스냅샷을 올리고 `/t/<id>`로 공개한다. 열람·드릴다운·퀴즈는 로그인 없이 되고, "내 기기에 복제"로 로컬 트리를 만든다. 작은 트리는 URL 해시에 압축해 서버 없이 링크로 보내는 방법도 있지만 URL 길이 한계가 있다 [미확인: 메신저별 URL 길이 상한].
    UX: 카페 글의 링크를 누르면 바로 드릴다운 화면이 뜨고, 하단에 "내 트리로 가져와 복습 시작" 버튼이 있다.
11. **복습 알림(웹 푸시)** — 설치한 PWA에서만 권한을 요청하고(#3 선행), 하루 1회 사용자가 정한 시각에 due 수를 보낸다. 서버는 due 수를 몰라도 된다. 정해진 시각에 빈 푸시를 보내고, 서비스 워커가 로컬 DB를 읽어 문구를 만든다 [추론: iOS는 무음 푸시를 허용하지 않아 알림을 반드시 띄워야 함, 미확인]. 서버가 없는 단계의 대안은 앱을 열 때 배지와 D-day를 강조하는 것이다.
    UX: 설정에서 "매일 21:30 복습 알림"을 켜면, 그 시각에 "오늘 복습 14장 · 스트릭 13일"이 온다.
12. **Google Drive 자동 백업** — 사용자가 Google 계정을 연결하면 #1 백업 파일을 `appDataFolder`(또는 보이는 폴더)에 하루 1회 올린다. 서버를 운영하지 않으니 11 §6의 개인정보 부담(유출 신고 의무)이 생기지 않는다. 대신 OAuth 동의 화면 검수 절차가 있다 [미확인: `drive.appdata` 범위의 검수 등급].
    UX: 설정의 "Google Drive에 자동 백업"을 켜면 "마지막 백업: 오늘 08:12"가 표시된다.
13. **계정 + 멀티 디바이스 동기화** — 11 §2의 Pi 서버와 OAuth를 쓴다. 로컬 DB가 기준이고, 변경 큐를 올리는 방식으로 오프라인을 우선한다. 노드 편집 충돌은 노드 단위 last-write-wins로 시작하고, 공동 편집(#14)이 필요해질 때 CRDT를 검토한다. 이 시점부터 처리방침·계정 삭제·전체 데이터 내보내기(#1 재사용)가 필수가 된다(11 §6, O3).
    UX: 폰에서 로그인하면 "PC의 트리 7개를 가져왔어요"가 뜨고, 이후 양쪽 편집이 몇 초 안에 맞춰진다.
14. **스터디 그룹 / 강사 배포** — 그룹장이 트리를 배포하면 구성원의 노드별 오답률을 익명으로 합쳐 "우리 스터디가 가장 많이 틀린 가지"를 보여 준다. 02의 저녁 스터디(목차 구두 발표) 루틴과 맞는다. 서버·계정(#13)이 먼저 있어야 하고, 사업 범위에서도 미뤘으므로 P2다.
    UX: 스터디 방 화면에 "이번 주 공통 약점: 부당해고 구제절차 (5명 중 4명 오답)"가 맨 위에 뜬다.
15. **Google Play TWA** — #3을 마친 뒤 PWABuilder로 패키지를 만든다. 결제가 없으니(11) 앱 내 결제 정책 이슈도 없다. 유입 효과는 불확실하므로 06 GTM 채널이 막혔을 때 시도한다.
    UX: Play 스토어에서 "드릴다운 백지"를 검색해 설치하면, 웹과 같은 데이터 구조로 열린다(기기 저장소는 웹과 분리되므로 #1·#13으로 옮긴다).

## 수익화 연결 (05·09 §6 vs 11)
- 09 §6 전제(유료): 유료 경계 3요소 중 "전체 기간 약점 기록" = #4·#7, "시험일 역산" = #8이다. 이 항목들은 무료 14일·유료 전체 기간처럼 **보이는 기간만 잠그고 데이터는 계속 쌓는** 구조로 만들어야 나중에 경계를 붙일 수 있다. 동기화(#13)와 Drive 백업(#12)은 RemNote·Obsidian처럼 유료 후보이기도 하다 [추론].
- 11 전제(무료·후원, 현재 기준): 잠금 없이 전부 무료로 제공한다. 운영비 회수는 설정 화면의 토스 송금 링크 하나로 끝난다(11 §3.3). 이 경우 별도 기능 개발이 필요 없어 표에 넣지 않았다.

## 분야 Top 3
1. **#1 전체 백업·복원** — 서버가 없는 지금 사용자 데이터를 지킬 유일한 수단이고(Safari 저장소 삭제 위험), #9·#12·#13이 모두 이 직렬화 형식을 재사용한다.
2. **#4 숙련도 대시보드** — 이미 쌓이는 attempts·srs 데이터로 페르소나 A의 핵심 불만("지난 약점을 다시 못 본다")을 풀고, 11의 성공 지표(회독별 재현율)를 사용자 가치로 바꾼다.
3. **#3 개선: 설치형 PWA 완성** — 아이콘 몇 장으로 끝나는 S 작업이다. 이것이 있어야 매일 재방문할 수 있고, 웹 푸시(#11)와 공유 수신(#9)도 열린다.
