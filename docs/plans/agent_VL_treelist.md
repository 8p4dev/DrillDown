# agent VL — 트리 목록 비주얼 다듬기 (orchestration_visual_polish.md §2 V4)

포트 5184. 이 파일이 진행 상황의 기준이다.

## 접근 방식
- **CSS 우선, 의존성 없음.** 동작 코드는 그대로 두고 마크업(아바타·SVG 아이콘·빈 상태 일러스트)과 `haptic()` 호출만 더한다.
- **아바타 색조 6종**: 제목 해시 → `data-tone="0..5"`. 색은 `--tone`에 토큰끼리의 `color-mix(in oklch, var(--accent) N%, var(--ok|--danger|--muted))`로 정의한다.
  - 대안 ① `oklch(from var(--accent) …)` 상대 색 문법: 지원 범위가 좁고, var()가 든 선언은 폴백이 안 된다.
  - 대안 ② `color-mix(in srgb, …)`: 색상 혼합이 탁해진다.
  - 채택안은 하드코딩 색이 없고 토큰만 쓰므로 다크 모드에서 자동으로 따라간다. 대비는 스크립트로 잰다.
- **아바타는 `pointer-events: none`**: `.tree-top > *`가 포인터를 살리므로 되돌려야 아바타를 눌렀을 때 뒤의 편집 링크가 눌린다. 장식이라 `aria-hidden`.
- **터치 크기**: `@media (max-width: 760px), (pointer: coarse)`로 함께 키운다(폭 기준 모바일 + 터치 태블릿). 1열 전환만 `max-width: 760px`.
- **햅틱**: 링크 `onClick`에서 동기 호출만 한다(preventDefault 없음). 제목 한 번 클릭은 더블클릭 판별 뒤(타이머 안)에서 호출해 더블클릭 때 울리지 않게 한다.

## 가정
- 영문 제목의 이니셜은 CSS `uppercase`로 대문자로 보인다. 결합 이모지(국기 등)는 첫 코드포인트만 보인다. 드문 경우라 `Intl.Segmenter`는 쓰지 않았다.
- 이름을 바꾸면 해시가 달라져 아바타 색도 바뀐다. 색을 저장하지 않는 설계의 자연스러운 결과로 본다.
- 만들기 폼의 입력칸·버튼과 머리의 내보내기 버튼, ⋯ 메뉴 항목도 함께 44px로 맞췄다(§2에 명시되진 않았지만 같은 터치 목표).
- 새 카드 등장은 `rise`에서 `spring-in`으로 바꿨다(§3.1 공유 keyframes, 손맛).

## 변경 사항
- 아바타 글자 색의 tone 비율을 72% → 65%로 낮췄다. 72%에서 라이트 모드 tone 4가 4.4:1로 AA에 못 미쳤기 때문이다.
- 계획에 없던 작은 수정 2건: 메뉴 항목에 남던 전역 버튼 그림자 제거, 터치 기기에서 이름 변경 입력칸이 카드 높이를 밀지 않도록 음수 여백 추가.
