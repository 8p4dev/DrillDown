# agent VD — 빈칸 퀴즈 · 백지 퀴즈 비주얼 다듬기

담당: `orchestration_visual_polish.md` §2 V3 1~5. dev 포트 5183. 브랜치 `rob8p4dev/agent-VD-dnd`.

## 접근 방식
- **맞춤**: `TreeCanvas`가 `ResizeObserver`로 캔버스 폭을 재서 `transform: scale(폭/그래프폭)`(.6~1)을 준다. 바깥 래퍼를 축소된 크기로 잡아 스크롤 영역을 맞춘다. 판정은 `elementsFromPoint`·`getBoundingClientRect`를 쓰므로 transform을 그대로 따라간다.
- **좁은 폭 좌→우 배치(가정 D1)**: §아래 참고. 캔버스 폭 ≤ 640px이면 `layout()` 결과의 축을 바꾼 `sideLayout`(dnd.ts, 순수 함수 + check)을 쓴다.
- **rAF**: `useDragDrop`이 드래그 중에만 rAF 루프를 돌린다. 프레임마다 `dropAt`과 기울기를 계산하고 값이 바뀐 때만 `setDrag`한다. 드롭 판정은 지금처럼 pointerup 이벤트 좌표로 하므로 지연된 상태를 쓰지 않는다.
- **기울기**: 프레임당 이동량 → ±4°, 프레임마다 목표로 감쇠. 포인터가 멈추면 0으로 돌아온다. CSS 변수 `--tilt`로 넘겨 reduced-motion에서는 CSS가 끈다.
- **모바일 시트**: 트레이+막대를 `.dnd-dock`으로 묶어 `position: sticky`. 흐름 안에 있어서 끝까지 스크롤하면 캔버스 마지막 줄이 가려지지 않는다.
- 대안: `zoom` CSS(계획이 transform 지정), 드래그 중 자동 스크롤(탭 놓기가 있어 생략).

## 가정
- D1 **390px 완료 기준 vs 최소 배율 .6**: 예제 트리는 리프 6개, 폭 1072px이라 .6으로 줄여도 643px > 캔버스 360px. 축소만으로는 기준을 못 맞추고, 배율을 더 낮추면 글자를 읽을 수 없다. 그래서 폭 ≤ 640px에서는 좌→우 트리로 놓는다(카드 폭은 96~148px로 유동, 보통 배율 1). 그래도 넘치면(깊이 6 이상) .6까지 축소 후 가로 스크롤.
- D2 원본 `offset`은 좌→우 배치에서 무시한다(축이 달라 의미 없음). 위→아래는 기존과 같다.
- D3 채점 후 모바일에서는 트레이를 흐름으로 돌리고 막대만 하단 고정한다(결과 트리를 시트가 가리지 않게).
- D4 트레이 카드의 `touch-action: none`은 유지한다(위로 끌기와 세로 스크롤을 구분할 수 없다). 트레이 스크롤은 좌우 여백·카드 사이 틈으로 한다.
- D5 집기 `haptic('tap')`은 드래그 시작과 탭 선택 때 낸다(pointerdown은 스크롤성 터치에도 울리므로 제외).
- D6 루트 엣지는 V1-5와 같은 accent 계열로 한다.

## 변경 사항
- 좌→우 배치(`sideLayout`)를 추가했다. plan §V3-1의 축소만으로는 390px 기준을 못 맞춘다(가정 D1).
- 모바일에서 `main`·`section`·`.dnd`를 세로 flex로 바꿨다. sticky만으로는 내용이 짧을 때 시트가 화면 중간에 떴다.
- 넓은 트레이 카드(> 148px)를 집으면 고스트를 112px로 줄인다. 그대로면 빈칸보다 넓어 화면 밖으로 잘렸다.

## 한계·미결
- E2E는 지시대로 실행하지 않았다. 실기기(iOS/Android)도 미확인이고 진동은 스텁으로만 확인했다.
- 640px < 캔버스 < 1072px(예: 800폭)에서는 6리프 트리의 글자가 약 9px까지 작아진다(§V3-1대로 transform 축소).
- 모바일 트레이는 카드 위에서 스크롤되지 않는다(가정 D4). 드래그 중 자동 스크롤은 없어서, 화면 밖 빈칸은 탭 놓기로 채운다.
- 토스트(V0)가 표시되는 동안 모바일 시트 막대와 겹친다(개요 가져오기 직후 이동한 경우). 사라지면 해소되고, Toast는 소유 범위 밖이다.
- 기존 동작(이번 변경 아님, 코드 읽기로만 확인): D1에서 접힌 노드의 하위 리프는 빈칸 없이 트레이 카드만 나온다(`layout`은 접힘을 숨기는데 `leavesOf`는 세기 때문). "기능 그대로" 범위라 고치지 않았다.
