## 4. 공통 규칙 (모든 워커 spec 에 포함)
1. 소스 코드·설정·스펙 수정 금지. 쓰는 파일은 자기 보고서 1개 + `.research-data/<ID>/`·스크래치 스크립트뿐. 커밋 금지(오케스트레이터가 커밋).
2. `npm run build`·`npm run e2e`·`npm install` 금지(공유 워크트리). `dist/` 는 최신 빌드. 앱이 필요하면
   `PORT=<포트> HOST=127.0.0.1 AUTH_FAKE=1 DATA_DIR=.research-data/<ID> PUBLIC_ORIGIN=http://127.0.0.1:<포트> node server/index.ts` 를 백그라운드로 띄우고 끝나면 그 PID 만 종료(광역 kill 금지). 5173 은 사용자의 프리뷰 — 건드리지 않는다.
3. 브라우저 확인은 임시 Playwright 스크립트(스크래치 디렉터리, `channel:'msedge'`)로. 가짜 로그인 `/api/auth/fake/start?as=user&name=<ID>&return_to=%23%2F`. 예시 트리는 목록 → 트리 편집 → "개요 텍스트"에 outline 파일 내용 붙여넣기로 만들 수 있다(직접 확인). 트리 다수는 같은 방식 반복 또는 page.evaluate.
4. 근거 우선: 각 문제에 **재현 절차 또는 코드 위치(`path:line`)** 를 단다. 추측이면 "추정" 표시. 스크린샷은 `docs/research/many_trees/img/<ID>_*.png`(필요할 때만, 5장 이하).
5. 보고서 형식(한국어):
   - 요약 3줄
   - 문제 표: `ID | 문제(사용자 말로) | 언제 겪나(트리 n개/노드 n개 등 임계) | 심각도(치명/높음/중간/낮음) | 근거`
   - 해결안 표: `문제ID | 방안 | 대안 | 공수(S/M/L) | 효과 | 위험·부작용 | 자체 평가(채택/보류/기각 + 이유)` — 방안마다 "더 단순한 방안은 없나"를 먼저 따진다
   - 이미 잘 되는 것(재확인한 것) 짧게
6. 끝나면 `worker_done` 에 보고서 경로·문제 수·상위 3개를 적는다. 막히면 `ask`.
