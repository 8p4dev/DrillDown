# agent VE — 에디터 비주얼 다듬기 (orchestration_visual_polish.md §2 V1)

## 접근 방식
- **배율 변경 공통 함수 `zoomTo(next, cx?, cy?)`** (EditorPage): `.graph` 의 rect 로 기준점의 그래프 좌표를 구하고, `flushSync` 로 배율 적용 뒤 다시 잰 rect 로 스크롤을 보정한다. 버튼·키는 캔버스 중앙, Ctrl+휠은 커서, 핀치는 두 손가락 중심이 기준점.
  - 대안: 레이아웃 공식으로 스크롤 계산 → flex 가운데 정렬 여부를 분기해야 해서 rect 재측정이 더 짧고 정확하다.
- **진입 맞춤**: GraphView 의 기존 "측정 완료(known 갱신)" 분기에서 `onSettled(w, h)` 를 부른다. EditorPage 는 `fitPending` ref 가 켜져 있을 때 1회만 넘침을 판정해 `min(1, 가용폭/w, 가용높이/h)`(하한 .5)로 맞추고 루트를 가로 중앙으로 스크롤한다. FALLBACK 크기로는 판정되지 않는다.
  - 레이아웃 이펙트 안에서는 flushSync 불가 → setZoom 후 `[zoom]` 레이아웃 이펙트에서 스크롤(페인트 전).
- **떠 있는 툴바**: `.outline`(스크롤러, role=tree) 밖에 `.canvas` 래퍼를 두고 `.zoom-tools` 를 absolute 로 띄운다. role=tree 안에 버튼을 넣지 않기 위함이고, 스크롤에 따라 움직이지 않는다.
- **핀치**: `.graph-pan` 의 capture 단계 포인터 핸들러에서 touch 포인터를 Map 으로 추적. 2개가 되면 카드 드래그·패닝을 취소하고, 손가락이 모두 떨어질 때까지 드래그·패닝 시작을 막는다. `touch-action: none` 을 `.graph-pan` 전체로 넓혀 브라우저 제스처와 충돌을 막는다.
- **성능**: 렌더당 1회 `useMemo` 로 하위 수 맵 계산(O(n)), `layout`·`shown`·`moving` useMemo. 추가로 `NodeRow` 를 `memo`(콜백 `on*` 제외 비교). 콜백은 모두 ref(`nodesRef`, `editRef`, `draftRef`)만 보거나 setState 라 낡은 클로저여도 안전하고, 편집 중 카드는 draft 변경으로 매번 새로 렌더된다. 핀치·휠 줌 때 카드가 다시 렌더되지 않는 이득도 있다.
- **새 카드 스프링**: 모든 카드에 애니메이션을 걸면 진입 시 300장이 동시에 튄다 → 첫 정착 이후 마운트된 카드에만 `.spawn` (마운트 시점 값 고정).
- CSS 는 토큰만 사용, 호버는 `@media (hover: hover)` 안으로 이동.

## 검증 방법
- 임시 Playwright 스크립트(스크래치패드, msedge): 스크린샷, 배율·좌표 확인, CDP 터치 이벤트로 핀치. e2e 는 실행하지 않는다.
- 성능: 프로덕션 빌드에서 `dispatchEvent('input')` → 동기 렌더·커밋·패시브 이펙트 후 다음 태스크까지 `performance.now()` 차이. 측정 코드는 스크래치패드에만 둔다.

## 가정
- 개요 가져오기도 "처음 불러오기"로 본다. 가져온 뒤 1회 넘침을 판정해 맞추고 캔버스를 화면으로 스크롤한다. 빈 트리에 개요를 넣는 것이 사실상 진입이고, §4 A4 모바일 스모크("개요 가져오기 → 루트가 화면 안에 보임")가 이를 요구한다. 일반 편집(노드 추가·이동·너비)에서는 맞추지 않는다.
- 카드 폭 단계는 모바일(≤760px)에서 120/190/280px로 좁힌다. 180px 카드는 최소 배율 .5에서도 1단계 카드 폭 합이 498px라 390px 화면에 들어오지 않아 V1-1 완료 기준을 채울 수 없다. `data-width` 와 저장값은 그대로이고 화면 폭만 다르다.
- 한 손가락 패닝을 빈 배경 전체에서 받으려고 `touch-action: none` 을 `.graph-pan` 전체로 넓혔다. 모바일에서 페이지 세로 스크롤은 캔버스 밖(헤더·패널)에서 한다.
- "accent 25%" 엣지는 `color-mix(accent 25%, --border-strong)` 로 해석했다. 투명도 25%는 다른 엣지보다 흐려진다.
- 단축키 하단 시트는 1단 배치 전체(≤860px)에 적용한다. 도구가 캔버스 아래쪽으로 옮겨가 761~860px 구간에 고정 좌표를 줄 수 없기 때문이다.

## 변경 사항
- 계획에 없던 수정: 전역 입력칸 규칙(`input:not():not()`)의 우선순위가 `.title-input`·`.detail-title` 보다 높아 테두리·`min-height` 가 카드 입력칸에 새고 있었다. 선택자를 높여 해결했다.
- 데스크톱 `main` 아래 여백을 줄이고 캔버스 높이를 `100dvh - 9.25rem` 으로 맞췄다. 떠 있는 도구가 스크롤 없이 항상 보이고 페이지 스크롤도 생기지 않는다(1280×720 에서 문서 높이 = 화면 높이).
- 루트 중앙 스크롤은 카드 rect 대신 배치 좌표를 쓴다. 가져오기 직후 루트가 `left` 트랜지션 중이라 rect 가 옛 위치를 가리켜 중앙에서 벗어났다.

## 측정 결과
조건: 301노드, 프로덕션 빌드, 1440×900, msedge. 40회 입력의 값이다. 다른 워커가 동시에 돌아 벽시계 값은 잡음이 크다.

| 지표 (입력 1회당 ms) | 전 | 후 |
|---|---|---|
| 카드 제목, 벽시계 중앙값, 배속 1x (실행별) | 10 / 10.8 / 11 | 6.8 / 5.2 |
| 패널 제목, 벽시계 중앙값, 배속 1x (실행별) | 6 / 8.7 / 7 | 6.4 / 5.6 |
| 카드 제목, 스크립트 시간, CPU 6x 스로틀 (실행별) | 28.6 / 27.4 / 24.7 | 15.2 / 13.1 / 12.1 |
| 패널 제목, 스크립트 시간, CPU 6x 스로틀 (실행별) | 42.1 / 26.8 / 26.3 | 29.7 / 17.5 / 18.7 |
| 카드 제목, 벽시계 중앙값, CPU 6x 스로틀 (위와 같은 실행) | 54.1 / 53.1 / 51 | 47.4 / 41.1 / 41.8 |
| 패널 제목, 벽시계 중앙값, CPU 6x 스로틀 (위와 같은 실행) | 73.9 / 44.9 / 45.5 | 69.3 / 38 / 35.1 |

- 측정 방법: `dispatchEvent('input')` 부터 다음 태스크까지 `performance.now()` 차이(렌더·커밋·패시브 이펙트 포함), 스크립트 시간은 CDP `Performance.getMetrics` 의 `ScriptDuration` 증가분. 측정 코드는 커밋하지 않았다.
- 결론: 스크립트 시간은 카드 제목에서 약 절반, 패널 제목에서 약 30% 줄었다. 레이아웃 시간(약 3~5ms)은 변화가 없다. 렌더마다 카드 크기를 재는 `measure()` 는 그대로 두었다.
- 스크립트 시간 측정 전에 따로 돌린 CPU 6x 벽시계 중앙값은 잡음이 커서 구분되지 않았다(카드 전 71.6 / 71 / 61.9 / 90.5, 후 85.5 / 52.9 / 45.5 / 88.1). 위 표의 수치와 함께 보아야 한다.

## 화면·동작 확인 (임시 Playwright 스크립트)
- 390×844: 9노드 트리 진입·가져오기 모두 50%, 루트와 1단계 카드 3장이 캔버스 안, 가로 페이지 스크롤 없음. 패널 도구 버튼 36×36, 떠 있는 도구 44×44.
- 1280×720: `extras.spec.ts` 의 6노드 트리는 100% 유지, 확대 120% → Minus 100% → 83%, 83%에서 83px 끌기 = 배치 100px, `자동 정렬` 표시, 배율 클릭·`0` = 100%, 편집 후 배율 유지.
- 터치(CDP): 배경 핀치 50 → 150%, 카드 위 핀치 38 → 62%이고 카드는 끌리지 않음(`자동 정렬` 없음), 한 손가락 패닝 동작.
- Ctrl+휠: 스크롤 여유가 있는 축에서 커서 아래 지점 이탈 0px. 세로로 넘치지 않으면 위로 스크롤할 수 없어 세로 이탈이 남는다(확인값 51px).
- 메모 된 카드의 콜백 확인: 너비 핸들, 접기 배지, 제목 편집·패널 실시간 반영, 삭제·실행 취소 정상.
- 다크 모드 1440×900 스크린샷 확인. 실기기 테스트와 `npm run e2e` 는 하지 않았다.

## 미해결
- **오케스트레이터 확인 필요**: `core-flow`·`modes` 의 9노드 트리(3×2, 폭 1264px)는 1280×720 캔버스(907px)를 넘친다. 지시와 달리 가져온 뒤 배율이 70%가 된다. 100% 기준 좌표를 쓰는 `extras.spec.ts` 확대 테스트는 6노드 트리(폭 652px)라 100%를 유지한다. `core-flow` 너비 핸들 단계는 70% 조건에서 재현해 통과했다.
- 첫 손가락이 너비 핸들 위에 있을 때 두 번째 손가락을 대면 너비 조절과 핀치가 함께 동작한다(핸들은 카드 끌기와 별도 경로). 두 번째 손가락으로 핸들을 잡는 경우는 막았다.
- 모바일에서 최소 배율 50%의 카드 글자는 작다. 전체 트리(폭 452px)는 390px에 다 들어오지 않고, 2단계 이하 양 끝 카드는 패닝해야 보인다.
- 체감(스프링 세기 등)은 사용자 확인 대상이다.
