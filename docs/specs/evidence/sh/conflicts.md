# 동기화 충돌 시나리오 표 (SH, 2026-11-08)

규칙(04 §3.1): 엔티티(트리 1행·노드 1행·srs 1행) 단위 **LWW**. 비교 키는 `updatedAt`(클라이언트 epoch ms), 같으면 서버에 먼저 도착한 쪽이 이긴다. 삭제는 `deletedAt = 삭제 시각`을 가진 톰스톤이며 put과 같은 규칙으로 비교한다(삭제도 "쓰기"다). 적용 후 부모가 없는 노드(고아)는 루트 자식으로 되살린다(`updatedAt = now`, 다시 push).

표기: A·B = 같은 사용자의 두 기기. "A보다 나중"은 B의 `updatedAt`이 더 늦다는 뜻. 기대 결과는 양쪽 기기가 동기화를 마친 뒤 **둘 다 같은 상태**여야 한다.

## 결과 일관성 확인(머리로 돌린 검증)
- 모든 행은 "엔티티 단위 LWW + 톰스톤도 쓰기 + 고아 → 루트"의 세 규칙만으로 결정된다. 기기 순서를 바꿔 적용해도(A 먼저 push, B 먼저 push) 서버 최종 상태가 같다: 비교 키가 도착 순서가 아니라 `updatedAt`이기 때문(동률만 도착 순).
- 고아 복구는 양쪽 기기에서 각자 실행돼 `updatedAt`이 다르지만 결과(parentId=root)가 같아 LWW가 어느 쪽을 골라도 상태는 같다.
